# Gate 2b - JSON test spec generation (AGENT-GENERATE)

Gate 2b requires a COMPLETE JSON spec. An incomplete spec makes the Magik agent loop
and fail. Run this checklist BEFORE submitting any gate 2b response. Follow gate.magik_prompt
exactly - it is the specification. Do NOT produce a simplified spec based on your own judgment.

## Step 1 - Mandatory re-read
Re-read EVERY file in gate.file_paths completely, line 1 to last line, in THIS step. Do NOT
rely on earlier reads or memory. Return read_receipts for every file read.

## Step 2 - Top-level sections (ALL required)
Verify these keys exist in the output JSON:
- screenName
- fileName
- filePath
- associatedFiles
- moduleName
- description
- rootFile (fileName, filePath, describesUrl, containsTriggers[])
- modalFiles[]
- techStack (framework, stateManagement, uiLibrary[], notifications[], httpClient, caching)
- functionalitySummaryTable[]
- functionalities[]
- dependencyGraph
- validationMatrix[] - each entry must have errorDisplayMode: toast|inline|both
- apiMappingSummary[] - each entry must have callerFunction
- responseCodeMappingSummary[]
- permissionsMatrix
- modalsSummary[]
- notificationsSummary
- inlineErrorsSummary
- loaderHandling
- selectorAudit[]

## Step 3 - Per functionality (ALL required for each entry in functionalities[])
Every functionality object must contain:
- id, screenName, functionality, description
- rootFile, modalFile
- modalDetails: modalName, modalSelector, trigger, triggerSelector, conditions[]
- submitButton: label, className, selectors[], hiddenInModes[]
- cancelButton: label, className, selectors[]
- fields[] - see Step 4
- notifications: library, containerSelector, messageSelector, typeSelectors{}, selectors[], messages[]
- inlineErrors: library, selectors[], positionRelativeToField, messages[]
- apiIntegration: endpoint, method, headers[], queryParams[], pathParams[], requestPayload{}, responseStructure{}
- responseHandling: successCodes[], failureCodes[], validationCodes[], successMessages[], failureMessages[], toastMessages[], inlineErrorMessages[], navigationFlow
- businessLogic[]
- dependencies[]
- stateManagement: statesUsed[], settersUsed[]
- eventHandlers[]
- notes[]

## Step 4 - Per field (ALL required for each entry in fields[])
Every field object must contain:
- label, fieldName, variableName, type, required, defaultValue
- domSelectors[] - VERIFY in JSX whether id/name attributes actually exist; if not, use
  placeholder or label-proximity selectors
- interactionPattern: default | react-select | datepicker | checkbox | radio | rich-text | file-upload
- optionSelectorPattern (for dropdowns)
- dateFormat (for datepickers)
- validations: regex, minLength, maxLength, customRules[]
- conditionalLogic
- readonly, disabled
- dropdownSource, dropdownOptions[]
- placeholder

## Step 5 - Self-check before submitting
Answer YES to ALL before returning json_spec:
- Every file in gate.file_paths fully re-read in this step (not from memory)
- techStack block is present and populated
- Every functionality has: businessLogic[], stateManagement{}, eventHandlers[], responseHandling{}
- Every field has: interactionPattern, placeholder, readonly, disabled, conditionalLogic
- domSelectors verified against actual JSX (no invented name= or id= attributes)
- Every notification call site (pushNotify, toast, NotificationManager) documented with exact text
- Every inline error (errorsMsgs[field], <FormFeedback>, label.default-validateLabel) documented
- selectorAudit lists EVERY selector used anywhere in the spec
- No section is empty, placeholder text, or missing
- read_receipts included with path, line_count, last_line for every file read

## Common mistakes to avoid
- Generating a simplified spec and submitting silently - VIOLATES rule 2b-5
- Skipping techStack, businessLogic, stateManagement, eventHandlers - these are required
- Using input[name="x"] when JSX has no name attribute - use placeholder or label proximity instead
- Using apiCalls[] instead of apiIntegration{} - wrong schema key
- Skipping notes[] per functionality - the agent uses these for context
- Not resolving getNotification("KEY") to actual text - document the key AND the resolved text

## ICX enforcement
After you submit, ICX checks the sections below are present (and, for REQUIRED_SECTIONS,
non-empty), including per-functionality and per-field keys, and re-asks you naming exactly
what is missing until the spec is complete. ICX never silently submits an incomplete spec.
Only after the user has reviewed and KNOWINGLY accepts an incomplete spec may you resume
with accept_incomplete:true. Edit the marker lists below to match your Magik version's schema;
ICX enforces exactly what is listed.
